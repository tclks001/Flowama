# 三维颗粒调试切片

## 目的与范围

当前程序是后续流麻模拟的最小三维颗粒验证：确认容器坐标、固定展示视图、固定步长、256 个亮粉的沉降与堆积、六面边界约束和最小 OpenGL 绘制能够共同工作。

它不是流体模拟，也不是正式摆件渲染。固定展示视图在程序初始化时确定一条屏幕向下的显示重力；当前容器姿态会将它转换为容器局部重力。它能表达静止或缓慢倾斜时的下落方向，尚不包含容器加速度和旋转造成的非惯性力。

## 运行与操作

~~~powershell
.\scripts\build.ps1
.\build\windows-debug\flowama.exe
~~~

- 左键拖拽：按固定展示视图的屏幕上、右方向旋转容器，并在固定步边界记录容器姿态；容器在画面中的旋转方向与拖拽方向一致。
- R：重置容器和粒子，并开始一条新的姿态记录。
- scripts/verify.ps1 -Ticks 120：隐藏窗口运行 120 个固定模拟步。
- scripts/capture.ps1：以同一初始状态输出固定 tick 的 BMP 截图；运行方式见 automation-and-capture.md。

## 运行时数据流

~~~text
SDL 事件
  -> ContainerPose（左键容器旋转）
  -> 姿态记录或自动化姿态轨迹
  -> 固定显示重力转换为容器局部重力
  -> GranularSimulation（120 Hz 固定步长、接触迭代）
  -> DebugRenderer（容器模型矩阵、线框、重力箭头、点精灵）
~~~

## 坐标与相机

容器局部坐标从一开始就是三维：

~~~text
x：横向
y：厚度／前后方向
z：竖向
~~~

薄盒全尺寸为 3.6 x 0.2 x 6.0。展示相机以盒心为固定观察目标，保存固定相对位置 position_ 和上方参考 upHint_。实际相机基向量由下式推导：

~~~text
forward  = normalize(-position)
right    = normalize(cross(forward, upHint))
screenUp = normalize(cross(right, forward))
~~~

upHint 不是屏幕上方本身；它可能含有沿 forward 的分量。推导 screenUp 相当于从 upHint 中去掉该分量，得到与相机前向正交的真实屏幕向上方向。相机基向量在运行中不改变。

左键拖拽以固定相机局部轴作增量轴角旋转：水平拖拽绕 screenUp，垂直拖拽绕 right。容器的增量符号与相机围绕容器观察时的符号相反，因此盒体在屏幕中的偏移方向与拖拽方向一致。底层姿态仍使用四元数，记录与回放不依赖鼠标像素或 Euler 角。

当前显示重力与局部重力为：

~~~text
displayGravityWorld = -screenUp * 9.81
localGravity = inverse(containerOrientation) * displayGravityWorld
~~~

screenUp 在展示相机创建后保持固定，因此显示重力也保持固定，并在画面中始终指向下方。渲染把局部线框、粒子和重力箭头共同乘以容器模型矩阵，因此倾斜后的容器仍显示屏幕向下的重力箭头。当前没有由平移、角速度或角加速度导出的非惯性项。

## 亮粉接触与堆积

当前亮粉群有 256 个等半径球形颗粒。它们从固定的、无重叠的三维晶格加微扰初始布局开始；微扰由粒子索引确定，因此重置、verify 与 capture 都能得到相同初始状态。单颗亮粉保存三维位置、上一步位置、速度和统一半径。每个固定步先按半隐式 Euler 预测位置：

~~~text
velocity += gravity * dt
position += velocity * dt
~~~

每个 120 Hz tick 随后执行 12 轮固定顺序的位置投影。每轮先用六个解析平面约束球心到 `halfExtents - particleRadius` 的范围；盒壁不使用虚粒子。对发生墙面法线修正的亮粉，切向修正最多为法线修正量乘墙摩擦系数。

粒子—粒子约束为：

~~~text
|xi - xj| >= 2r
~~~

宽相使用容器局部空间中的固定均匀网格，格宽为 `2r`。每轮只检查同格和 26 个相邻格，并以固定格序与粒子索引顺序只处理每一对一次。发生穿透时，两个等质量亮粉各承担一半法线分离修正；切向相对位移的修正量限制为 `particleFriction * penetration`，作为位置级库仑摩擦近似。完全重合时使用由粒子索引对确定的备用法线，避免 NaN 与非确定性随机方向。

当前 CPU 求解器使用顺序位置投影，以较少迭代获得稳定的局部堆积；它是本切片的可读基线，不是未来 GPU 并行求解器的最终形式。每个固定步结束后，以 `(position - previousPosition) / dt` 重建速度，因此所有位置投影（包括墙面和粒子接触修正）都会进入下一步速度。

运行时输出最后一轮的最大格子占用、候选接触对、发生穿透的接触对和最大残余穿透，用于发现异常单格坍缩；这些诊断不替代人工截图检查。

当需要检查堆积输入是否使 CPU 固定步变慢时，`scripts/tools/profile.ps1` 可对同一姿态轨迹输出平均与最慢 tick 的预测、盒壁、网格和接触耗时。它不测量桌面呈现或 GPU 时间，具体运行方式见 automation-and-capture.md。

## OpenGL 绘制

渲染器只使用一个顶点 Shader 和一个片元 Shader。

- 线框：CPU 构造薄盒八个角点和十二条边，使用 GL_LINES 绘制。
- 重力箭头：作为额外的三条线段，与线框使用同一路径。
- 亮粉：每帧上传 256 个 GL_POINTS 顶点。Vertex Shader 写入 gl_PointSize，Fragment Shader 通过 gl_PointCoord 丢弃圆外片元，得到圆形点精灵。
- 坐标变换：几何和粒子保存在容器局部坐标中；渲染使用容器的平移 × 旋转 Model 矩阵，顶点 Shader 接收 Projection * View * Model * localPosition。
- 深度：开启深度测试，使线框与点精灵按相机深度遮挡。

当前每次绘制都把调试线段或亮粉位置上传到同一个动态 VBO。该实现便于阅读；大量亮粉渲染会采用不同的数据布局与更新方式。

## 固定步长与确定性运行

交互模式将真实帧间隔累积到时间池中，并在每个渲染帧执行零到多个 1 / 120 s 模拟步。单帧间隔被限制为最多 0.25 s，且每帧最多运行 32 个子步，以避免卡顿后的无限追赶。

验证和截图模式不读取真实时间：每次循环恰好执行一个固定模拟步。因此 `--verify --ticks N` 或 `--capture --ticks N` 表示确定的 N 个模拟步，而不是 N 帧显示帧。

## 已知限制

- 当前只有 256 个等半径亮粉；没有多粒径、不同密度、颜色分层、真实滚动自旋或黏性流体速度场。
- 当前摩擦是为稳定堆积服务的位置级近似，不是带角速度与接触历史的完整颗粒动力学模型。
- 当前高速落地或薄盒侧壁压紧时，位置投影及其速度重建可能形成规则接触链和可见的上抛；它尚不能代表黏性流沙油中的过阻尼亮粉碰撞。后续接触模型需要分离几何非穿透修正与速度级非弹性响应、摩擦。
- 鼠标是逻辑拖拽状态，尚未启用系统级鼠标捕获。
- 没有容器表面、透明度、折射、珠光、阴影或正式 UI。
- 当前姿态轨迹只改变局部重力和渲染变换，不能用于验证平移惯性、角加速度、科里奥利力或移动端输入。

## 验证

- scripts/build.ps1 应成功构建。
- scripts/verify.ps1 -Ticks 120 与 -Ticks 720 应成功完成，并输出 256 个亮粉的质心、网格占用、候选对和残余穿透诊断。
- 人工运行时，亮粉应先向当前低侧沉降并形成不穿出六面盒壁的稳定堆积；左键任意方向拖拽后，盒体应沿同一画面方向倾斜，重力箭头保持屏幕向下，亮粉应向新的低侧滑动或重新堆积。姿态轨迹的详细契约见 container-motion-tracks.md。
