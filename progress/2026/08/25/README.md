## 已知问题与性能结论

- 项目所有者在桌面模式运行 `data/motion-tracks/recorded-20260825-174951.csv` 时观察到轻微、可感知的卡顿；记录覆盖 tick 0 至 4874，卡顿主要出现在亮粉向角落密集堆积后。
- 该轨迹的两次完整 `--profile` 回放得到稳定的平均 CPU 固定步成本：约 7.51 ms，其中粒子接触约 5.29 ms，盒壁约 0.83 ms，网格构建约 1.31 ms。最慢 tick 的位置在两次运行间从 4619 变为 2709，说明单个 16 ms 峰值包含 Debug/操作系统调度噪声，不应绑定为特定姿态的物理结论。
- 同一轨迹的前 600 tick 平均固定步为 6.73 ms、接触为 4.62 ms、候选对为 14,534；仅统计末段 tick 4000 至 4874 时，平均固定步升至 8.27 ms、接触升至 6.03 ms、候选对升至 17,918。密集堆积确实使正常接触工作增加。
- 末段单格峰值占用只有 3，完整回放峰值为 4；没有出现单桶坍缩或 `O(n²)` 的空间网格退化。当前瓶颈是 256 个颗粒在每个 120 Hz tick 内执行 12 轮顺序接触投影，而不是虚粒子边界或错误的网格哈希。
- 若桌面交换缓冲锁定在 60 Hz，每个显示帧平均需要追赶两个 120 Hz 固定步；末段仅模拟已约 16.54 ms，几乎耗尽一帧 16.67 ms 的预算，尚未计入事件、渲染、驱动和偶发轨迹缓冲写入。这足以解释当前“明显但非 PPT”的卡顿。剖析没有计 GPU、呈现或轨迹写入，因此不能量化它们的额外贡献。
