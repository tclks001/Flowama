## 关键发现

- upHint_ 是相机上方参考，不必与前向正交；ScreenUp() 通过叉积正交化得到真实屏幕上方。只有后者的反方向才能保证重力在屏幕上严格向下。
- 当前相机不是固定世界轴的 Euler yaw/pitch。它以当前屏幕上、右轴作增量旋转，因此无传统俯仰极点；现有退化保护在位置与上方参考共同旋转的前提下通常不会触发。
- 运行模式的区别应是时间、输入和输出策略，而不是不同的模拟实现。固定 tick 驱动应直接调用同一个 AdvanceFixedStep；截图仅在约定 tick 额外调用 RenderFrame 和像素写入。
- 1280 x 720 的 24-bit BMP 单帧约为 2.76 MB；在 120 Hz 模拟中每两 tick 截图一次会产生约 166 MB/s 的原始数据，并且每帧同步读回可能拖慢捕获。因此当前 capture 是离线验收工具，不以实时录制为目标。
